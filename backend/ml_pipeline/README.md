## 3. Step-by-Step Execution Guide

### Prerequisites
Install the required Computer Vision and Machine Learning libraries:
```bash
pip install ultralytics torch torchvision opencv-python numpy pillow requests
```

---

### Step 1: Image Collection from Wikimedia Commons
Collects real photographs (default: 5 per landmark for rapid development and testing, scalable up to 200–500) from Wikimedia Commons using open APIs. Automatically records contributor attribution, license tags (CC-BY, CC-BY-SA, Public Domain), and original image dimensions.
```bash
python scripts/01_collect_images.py --output ./data/raw_downloads --target 5 --delay 0.3
```
- Downloaded photos are organized by indexed class directories (`00_raigad_fort`, `05_gateway_of_india`, etc.).
- Complete licensing catalog is stored in `data/raw_downloads/dataset_metadata.json`.

---

### Step 2: Quality Filtering & Perceptual Deduplication
Purges corrupted files, filters out low-resolution images ($< 400\text{ px}$), and computes a **64-bit perceptual difference hash (dHash)** to eliminate duplicate or near-identical photographs (Hamming distance $\le 4$).
```bash
python scripts/02_clean_and_dedup.py --input ./data/raw_downloads --output ./data/cleaned_images --min-res 400 --hamming 4
```
- Retained unique images are stored in `data/cleaned_images/`.
- Perceptual hash registry is written to `data/cleaned_images/hash_registry.json` to prevent test-set leakage.

---

### Step 3: Bounding Box Annotation Workflow

#### Format Specification
YOLO expects text files with the same base name as the image (`.txt` instead of `.jpg`), where each line specifies one bounding box:
```text
<class_id> <x_center> <y_center> <width> <height>
```
All coordinates are normalized between `0.0` and `1.0`.

#### Option A: Saliency Proposal Generator + Human Verification
Run the automated contour saliency proposal generator:
```bash
python scripts/03_annotation_helper.py --action generate --images ./data/cleaned_images --labels ./data/candidate_labels
```
Next, visually inspect and adjust the boxes using LabelImg, CVAT, or Roboflow.

#### Option B: Manual Annotation Workflow (LabelImg)
1. Install LabelImg:
   ```bash
   pip install labelImg
   ```
2. Launch LabelImg:
   ```bash
   labelImg ./data/cleaned_images ./data/predefined_classes.txt ./data/candidate_labels
   ```
3. Set output format to **YOLO**. Draw tight bounding boxes enclosing the monument and save.

#### Option C: Audit & Validate Labels
Verify that all generated label files strictly conform to YOLO bounds:
```bash
python scripts/03_annotation_helper.py --action verify --labels ./data/candidate_labels
```

---

### Step 4: Stratified Leak-Proof Dataset Partitioning
Partitions the cleaned images and verified labels into a **70% Train / 20% Validation / 10% Test** split.
```bash
python scripts/04_split_dataset.py --images ./data/cleaned_images --labels ./data/candidate_labels --output ./YatraAI_Maharashtra_Dataset --train 0.70 --val 0.20 --test 0.10
```
- Output hierarchy matches Ultralytics standards:
  - `YatraAI_Maharashtra_Dataset/train/{images,labels}`
  - `YatraAI_Maharashtra_Dataset/valid/{images,labels}`
  - `YatraAI_Maharashtra_Dataset/test/{images,labels}`
  - `YatraAI_Maharashtra_Dataset/data.yaml`

---

### Step 5: YOLO11n Model Training

#### Option A: Local Training (GPU / CPU)
```bash
python scripts/05_train_yolo11.py --data ./YatraAI_Maharashtra_Dataset/data.yaml --model yolo11n.pt --epochs 100 --imgsz 640 --batch 16
```
- Training logs, weights, and curves are saved under `runs/train/yatraai_yolo11n_monuments/`.
- Top-performing weights (`best.pt`) are automatically copied to `backend/models/best.pt`.

#### Option B: Free Google Colab GPU Training (Recommended)
1. Zip your dataset:
   ```bash
   tar -czvf YatraAI_Maharashtra_Dataset.zip YatraAI_Maharashtra_Dataset/
   ```
2. Open `backend/ml_pipeline/train_yolo11_colab.ipynb` in [Google Colab](https://colab.research.google.com).
3. Set Runtime to **T4 GPU** (`Runtime > Change runtime type > T4 GPU`).
4. Run all cells. Download the resulting `best.pt` checkpoint.

---

### Step 6: Model Evaluation & Metric Reporting
Evaluates the trained model on the held-out test split ($10\%$ unseen photographs):
```bash
python scripts/06_evaluate_model.py --weights ./runs/train/yatraai_yolo11n_monuments/weights/best.pt --data ./YatraAI_Maharashtra_Dataset/data.yaml --split test
```
Outputs:
- **Precision ($P$)**
- **Recall ($R$)**
- **$\text{mAP}_{50}$** (Mean Average Precision at IoU 0.50)
- **$\text{mAP}_{50-95}$** (Mean Average Precision across IoU thresholds $0.50\text{--}0.95$)
- Per-class breakdown for all 19 landmark classes.
- Full JSON report saved to `runs/evaluation_report.json`.

---

### Step 7: Visual Inference & Testing
Tests detection on any unseen monument photograph, drawing bounding boxes, predicted landmark names, and confidence percentages:
```bash
python scripts/07_test_prediction.py path/to/test_photo.jpg --weights ../models/best.pt --conf 0.40
```
Outputs an annotated photograph (`test_photo_detected.jpg`) with bounding boxes and labels rendered.

---

## 4. Seamless Application Integration into YatraAI

Once training completes and `best.pt` is saved in `backend/models/best.pt`:
1. The **FastAPI Backend** (`backend/app/ai/yolo_detector.py`) automatically discovers and loads `best.pt` upon initialization.
2. The **Landmark Scanner Endpoint** (`POST /api/landmarks/scan`) performs real-time inference with bounding box coordinate extraction (`[x1, y1, x2, y2]`).
3. The **Next.js Frontend** ([`/scanner`](file:///d:/yatraai/frontend/app/scanner/page.tsx)) immediately transitions from *"Model not configured"* to live monument detection, displaying confidence scores, heritage information, and the direct *"View Details"* destination profile button.
